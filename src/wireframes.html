Switch / Segmented 切换

Switch 用于「开/关」型二值设置（显示描述/分类标签/分类色条），必须带 role="switch" + aria-checked。Segmented 用于「多档互斥」型枚举（主题/语言/布局/密度/名称显示），选中项以主色填充区分。只用 aria-pressed，不要两者混用。Source parts/04-interactions.js openSettings()。

Switch for booleans (role=switch + aria-checked); Segmented for mutually exclusive enums. Never mix aria-pressed into either. Source openSettings().

Pagination 分页

… 第 1 / 5 页

每页 36 条。窗口为「当前页 ±2 + 首尾必显」，中间以 … 省略；首页禁用「‹」、末页禁用「›」（disabled 而非隐藏）。翻页后 window.scrollTo({top:0,behavior:"smooth"}) 回到网格顶部；data-page 为 0 基。筛选/搜索/排序变化时页码重置为 0。Source parts/02-render.js renderPager()。

36/page; window = current ±2 plus first/last; disabled (not hidden) arrows at bounds; scroll to top on page change; reset to 0 when filters change. Source renderPager().

Vote 赞 / 踩

未投票 / 已赞 / 已踩

None / Up / Down

语义：赞与踩各自独立计数、互不抵消、可同时为正；再点同一项即取消该项。存储 localStorage["ash-votes"]，结构 {name:{up,down}}，原型 06-votes.js 与应用 lib/votes.ts 键名与结构一致。无后端聚合，数值仅代表本浏览器累计。

样式：描边常驻（未激活时透明底 + 浅描边），使激活态只换色不换尺寸，卡片不抖动；计数 min-width:2ch 预留两位数字宽度。

无障碍：颜色不是唯一区分手段——上下箭头形状不同，且 aria-pressed 同步状态；计数标 aria-hidden（对读屏而言 pressed 已表达「我是否投过」）。点击投票不得触发卡片打开，须在 #grid 委托中豁免 [data-vote-row]。

Independent up/down counters (not cancelling), toggle off on re-click, persisted in localStorage under "ash-votes". Border always present so activation changes colour only. Shape + aria-pressed carry state, not colour alone. Clicks must not open the card.

组件选型

先按下表确定「用哪个」，再翻到对应章节看变体。选错控件比样式不一致更难挽回。

需求用不要用理由
主行动（每屏至多 1 个）.btn.default多个并列实心按钮 实心按钮即「本页唯一主动作」，多个会互相争夺注意力
次级行动 / 并列操作.btn.outline / .btn.ghost.btn.default 降级视觉权重，保持主次分明
不可逆 / 破坏性操作.btn.destructive实心主色 破坏性动作不得占用主色，避免被误当默认路径
开/关 型设置Switch + role="switch"Segmented / Checkbox 二值语义用开关；多档互斥才用分段控件
多档互斥枚举（2–4 档）SegmentedSwitch / 下拉 档位少时全部可见优于折叠在下拉里
档位较多（≥5）select 下拉Segmented横向空间放不下，过长的分段控件会换行破版
分类筛选Chip 单选多选 Chip / 下拉 分类是单选语义（至多一个），且需常驻可见可点
卡片内打开详情<button class="card-open">整张卡片套按钮 整卡套按钮后无处安放赞/踩等次级按钮（会造成嵌套可交互元素）
表达「我赞过/踩过」Vote 赞踩行星级评分 / 净分 赞踩是两个独立维度，净分会掩盖「赞多但踩也多」的真实分歧
四舍五入的全库数字StatLedger + 「全库统计」标注与筛选结果混排 用户会误以为数字随筛选变化，必须显式区分全量 vs 实时
短暂反馈（复制成功等）Toast弹窗 / 内联提示 反馈不打断当前任务，弹窗会打断流程

状态矩阵

任何数据区都必须覆盖这四种状态；缺一即为不完整。详细视觉见 states.html。

状态触发呈现要点
加载中首屏 / 翻页拉取骨架屏（12 条）骨架形状须贴近真实卡片（色条 + 标题 + 两行描述），否则载入时布局跳变
有数据正常卡片网格 / 列表数字与文案全部来自真实数据，不内联假数据
空结果筛选无命中EmptyState必须给可执行的下一步（清除筛选），不能只说「无结果」
出错数据缺失 / 解析失败错误态 + 明确原因说明发生了什么、怎么修；不道歉、不使用模糊措辞

无障碍状态位

Accessibility states

已激活（主色填充） 常态（浅描边） 弱化 / 禁用 破坏性 / 踩

颜色永远不是唯一的状态载体：须同时具备形状差异（上下箭头 / 填充 vs 描边）或 aria-pressed / aria-checked，以满足色觉障碍与读屏用户。

组件使用红线

以下为硬性约束，违反视为缺陷而非风格偏好。
Hard constraints — violations are defects, not style preferences.
  1. 复用 tokens.css 的 CSS 变量，禁止硬编码颜色/间距/圆角。
  2. 图标统一内联 SVG，禁止引入其它图标库。
  3. 禁止嵌套可交互元素：按钮内不得再放按钮（卡片已改为容器 + .card-open）。
  4. 可交互元素须有 aria-label 或语义角色；弹窗标题用 sr-only。
  5. 动效仅 ~200ms 基准，缓动用 ease-out 系；全局兼容 prefers-reduced-motion。
  6. 业务数据只读来自 data/skills-data.json，不内联假数据。
  7. 样式优先定义在 prototype/src/styles/，与令牌同源；应用侧由 tools/sync-css.mjs 同步，勿手改 *-shared.css。
  8. 本模板与文案中禁止出现版本/日期占位符字面量（build.mjs 只替换模板中首个占位符，会被抢占）。
  9. 改动视觉令牌须同步本文件与 DESIGN.md，避免文档与实现漂移。
  1. Reuse tokens.css variables; no hardcoded colors/spacing/radii.
  2. Icons: inline SVG only; no other icon libraries.
  3. Never nest interactive elements (no button inside button).
  4. Interactive elements need aria-label / role; dialog title sr-only.
  5. Motion ~200ms baseline with ease-out; respect prefers-reduced-motion.
  6. Data read-only from data/skills-data.json; no fake data.
  7. Define styles in prototype/src/styles/; app side is synced — never hand-edit *-shared.css.
  8. Never write version/date placeholder literals in templates or copy.
  9. Keep this file and DESIGN.md in sync when tokens change.
